# Российские VIN-ориентированные источники для легковых VW / Audi / Škoda / SEAT

Проверка: 3 ноября 2026 года. Цель — найти источники для заводской комплектации, точной идентификации и последующего подтверждения ECU/ремонтной применимости. Наличие VIN-поиска само по себе не даёт права экспортировать данные в VAG TECH PRO.

## Кандидаты

### 1. Audatex / AudaVIN — главный кандидат для проверки заводской комплектации

URL: https://audatex.ru/services/using_vin

Сервис описывает VIN-запрос как способ получить список оборудования/вариантов оснащения, установленных на автомобиле на заводе. В списке поддерживаемых марок прямо присутствуют AUDI, SEAT, SKODA и VW. Результат изначально выдаётся как коды вариантов оснащения Audatex, затем может быть представлен текстом в калькуляции. Доступ требует подключения к AudaPad Web; расчёт тарифа/условий и API/экспорт нужно согласовать отдельно.

Что может подтвердить:
- наличие конкретных кодов заводского оснащения в результате VIN-запроса;
- комплектацию, если сервис действительно вернул результат для данного VIN;
- привязку к бренду и VIN в рамках самого отчёта.

Что не считать подтверждённым без отдельного поля/документа:
- заводской код двигателя или КПП;
- конкретный номер ECU, HW/SW, calibration ID;
- DTC и применимость диагностической процедуры;
- право на хранение/массовый экспорт/перераспространение результата.

Решение: запросить демонстрационный обезличенный отчёт и письменные условия API, хранения, извлечения структурированных фактов и использования в автономной некоммерческой базе.

### 2. VAGtec — каталог запчастей и проверка VIN заказа

URL: https://vagtec.ru/allnews/153-news-6

Страница сообщает об интерактивных копиях каталогов AUDI, VOLKSWAGEN, SKODA и SEAT и рекомендует указывать полный 17-значный VIN для согласования правильности подбора/заказа. Это полезно как дополнительная VIN-проверка каталожной применимости, но не доказательство ECU/диагностики/ремонтной процедуры. Публичные права на выгрузку и повторное использование не установлены.

Решение: запросить условия API/партнёрского доступа; не скрейпить каталог и не импортировать данные до письменного разрешения.

### 3. plan.parts VAG API — кандидат на интеграцию после проверки лицензии

URL: https://plan.parts/ru/databases/vag

Поставщик заявляет VIN decode, навигацию по ETKA, OEM-номера, exploded views и supersession chains для VW/Audi/Škoda/SEAT и Porsche. Публичная страница указывает тарифы токенов, но рекламное описание API не является подтверждением происхождения каждой записи и не устанавливает право включать результаты в распространяемую автономную базу.

Решение: запросить API-документацию, тестовый VIN-ответ, источник/версию данных и письменную лицензию на локальное кэширование и некоммерческое распространение.

### 4. Volkswagen Technical Site / VWTS — архив технических документов

URL: https://www.volkswagen.msk.ru/

Архив индексирует материалы VW/Audi/Škoda/SEAT, включая ремонтные руководства, двигатели, коробки и электрические системы. Он может быть полезен для поиска названий документов и контрольных примеров. Это не первичный портал производителя; правообладатель и разрешение на повторное распространение отдельных файлов должны проверяться для каждого документа.

Решение: использовать как поисковый указатель, не копировать и не включать документы в приложение без подтверждённых прав и точной применимости.

### 5. Официальные erWin для марок VAG

- Volkswagen: https://volkswagen.erwin-store.com/erwin/showStepByStep05.do
- Škoda: https://skoda-eu-qs2.erwin-store.com/erwin/showStepByStep05.do
- SEAT: https://seat-eu-qs1.erwin-store.com/erwin/showStepByStep05.do

Официальные страницы описывают VIN-идентификацию с выводом модели, модельного года и кода двигателя. В результатах поиска документов могут быть типовые ключи и, в зависимости от документа, коды двигателя/КПП. Содержимое доступно по действующему flat rate. Это лучший эталон для понимания структуры первичной OEM-применимости, но не разрешение на копирование или публикацию документов.

Решение: только авторизованный точечный доступ и отдельное письменное согласование прав на структурированные данные/факты; не автоматизировать массовую выгрузку.

## Что запросить у поставщика до интеграции

1. Пример обезличенного VIN-отчёта для VW, Audi, Škoda и SEAT (минимум по одному).
2. Пример исходного JSON/XML/CSV API-ответа, если API существует.
3. Полный список полей и семантику PR-кодов/опций.
4. Подтверждение охвата российского рынка и автомобилей российской поставки/импорта.
5. Разрешение на локальное хранение, резервное копирование и использование в некоммерческом автономном приложении.
6. Разрешение на включение производных структурированных фактов в распространяемую базу, а также условия обновления и удаления по требованию.

## Правило для импорта

До получения договора/письменного разрешения статус источника — `permission_required`. Полученные отчёты можно использовать для внутренней проверки только в пределах фактических условий поставщика. Ни один VIN, отчёт или идентифицирующее значение автомобиля не коммитить в публичный GitHub. Точные VIN хранить только локально в защищённой пользовательской базе, если это действительно требуется для диагностики.
